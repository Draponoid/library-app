# Архитектура и данные

Браузер загружает HTML, CSS и JavaScript с того же сервера, к которому отправляет JSON-запросы. Flask проверяет сессию и роль, валидирует данные, выполняет SQL и возвращает результат. SQLite сохраняет состояние между запусками.

| Хранение | schema.sql и файл data/library.sqlite3 |

| Эксплуатация | setup_local.py, start.ps1, /health, backup |

| Качество | tests/test_app.py, CONTRIBUTING.md |

## Связи предметной области

Автор → книги → экземпляры → выдачи. Филиал → экземпляры. Факультет → читатели → выдачи. Для всех этих связей используется отношение «один ко многим». У книги в версии 0.1.0 один основной автор. У библиотекаря факультет может отсутствовать.

Дополнительные таблицы sessions и audit_events хранят сессии и события изменения данных. Отчёты вычисляются по фонду и истории выдач. Их результаты не дублируются в отдельных таблицах.

## Содержательное правило

Один физический экземпляр может иметь не более одной незавершённой выдачи. Перед выдачей выполняется BEGIN IMMEDIATE; проверки доступности, лимита и просрочек, создание выдачи и запись аудита входят в одну транзакцию. Частичный уникальный индекс по copy_id при returned_at IS NULL защищает это правило и на уровне базы.

Читатель получает не более пяти книг одновременно и не может получить новую книгу, пока имеет просроченную. Стандартный срок — 14 дней; лимит и срок задаются в окружении. Возврат сохраняет историю и освобождает экземпляр.

## Защита данных

Пароли хранятся как scrypt-хеши. В cookie передаётся случайный токен, его хеш и срок сессии хранятся на сервере. Изменяющие запросы авторизованного пользователя требуют CSRF-токен. Роль проверяется на сервере. Внешние ключи запрещают удалять используемые записи.

<a id="tz-4-2"></a>

## 4.2 Правила данных

Книги содержат название, основного автора, год 1450–2100 и уникальный ISBN либо внутренний шифр. Экземпляр имеет уникальный инвентарный номер, книгу и филиал. Дата возврата и срок не могут предшествовать выдаче. Просрочка наступает на следующий день после due_at. Книги с экземплярами и экземпляры с историей не удаляются.

# 4 Требования к продукту продолжение

<a id="tz-4-3"></a>

## 4.3 Требования к системе в целом

Архитектура: браузер, единое HTTP-приложение и реляционная SQLite. Требуются русскоязычный интерфейс, JSON API и сохранение данных между запусками. Интерфейс должен быть пригоден для настольного экрана и ширины 390 пикселей без горизонтального переполнения страницы; широкие таблицы допускают собственную прокрутку.

Область эксплуатации версии 0.1.0 — локальная учебная установка и небольшой демонстрационный фонд. Целевые объёмы для приёмки: не менее 4 книг, 8 экземпляров, 4 авторов, 2 филиалов и 3 факультетов. Промышленная отказоустойчивость, распределённая работа и высокая нагрузка в эту версию не входят.

<a id="tz-4-4"></a>

## 4.4 Надёжность и целостность

Запись выдачи и возврата выполняется атомарно с аудитом. Внешние ключи и ограничения уникальности включаются в базе. Два одновременных запроса выдачи одного экземпляра должны приводить к одной успешной операции и одному отказу, без дубликатов. При ошибке транзакция откатывается.

Резервная копия создаётся средствами SQLite без перезаписи существующего файла. Восстановление производится после остановки приложения переключением DATABASE_PATH на сохранённую копию. Критерии проверки: integrity_check возвращает ok, каталог открывается и контрольные записи сохранены.

<a id="tz-4-5"></a>

## 4.5 Безопасность и обработка ошибок

Пароль читателя имеет длину 10–128 символов; в БД хранится только хеш. Серверная сессия по умолчанию действует 8 часов; cookie использует HttpOnly и SameSite=Lax. Роль проверяется на сервере. Изменяющие запросы требуют CSRF-токен действующей сессии. Параметры SQL передаются отдельно от текста запросов.

Ошибки возвращаются в JSON с кодом и сообщением. Предусмотрены 400, 401, 403, 404, 405, 409, 413, 422 и 500. В ответе 500 отсутствуют детали внутреннего стека. Размер тела ограничен 64 КиБ. Чужой Origin отклоняется. Debug-режим выключен.

<a id="tz-4-6"></a>

## 4.6 Виды обеспечения и программная среда

Информационное обеспечение: справочники и история в SQLite; схема описана в schema.sql. Лингвистическое: русский интерфейс, UTF-8. Программное: Python 3.11+, Flask 3.1.2, python-dotenv 1.1.1, HTML, CSS, JavaScript без сборщика. Техническое: компьютер с Python и браузером Chromium; интернет требуется для установки зависимостей. Конфигурация задаётся переменными окружения и файлом .env; образец поставляется без рабочих секретов.

Документы предоставляются на русском языке в электронном виде: отчёт с титульным листом и ТЗ в PDF, редактируемый текст в HTML и Markdown, исходные файлы приложения в UTF-8. Комплект передаётся единым ZIP-архивом. В интерфейсе, VERSION и документации используется номер 0.1.0.

# Запуск и демонстрация

## Первый запуск в Windows

Распаковать архив, открыть терминал в папке library-app и выполнить команды по порядку:

```text
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe setup_local.py
.venv\Scripts\python.exe app.py run
```

Открыть http://127.0.0.1:5000. Первичная настройка создаёт случайные пароли и выводит их в терминал; логины — librarian и reader. Пароли сохранены в локальном .env. Повторно выполняется только команда запуска сервера.

## Демонстрация преподавателю

1. Показать /health, выполнить вход библиотекаря и поиск книги. 2. Добавить автора, книгу и экземпляр. 3. Оформить выдачу читателю, показать срок и недоступность экземпляра для новой выдачи. 4. Принять возврат, открыть историю, отчёты и журнал. 5. Войти как читатель и показать ограниченный доступ. 6. Запустить тесты, открыть ТЗ, схему данных и правила приёмки.

## Резервное копирование

```text
python app.py backup --output backups/library-copy.sqlite3
```

Для восстановления остановить сервер, сохранить текущую базу и переключить DATABASE_PATH на файл копии. После запуска проверить /health и каталог. Копию с пользователями и сессиями хранить отдельно от публичного комплекта.
