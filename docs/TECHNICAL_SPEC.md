Основание: задание к лабораторной работе №1 «Сквозной проект и Git-процесс», вариант 3 «Библиотека», включая дополнение об обязательной аутентификации от 18.09.2026. Договор и отдельный шифр темы не назначены.

<a id="tz-1-3"></a>

### 1.3 Заказчик и исполнители

Учебная организация: Московский политех. Исполнители: Махров И.М., Крамской И.М., группа 241-351. Представитель заказчика и лицо, принимающее работу: преподаватель дисциплины «Методология и практики DevOps»; ФИО заполняется при сдаче.

Результат передаётся архивом с исходным кодом и документацией. Дополнения оформляются новой редакцией ТЗ с описанием изменённых требований и согласуются до приёмки. Git-репозиторий и операции Git исключены из состава данного комплекта.

# 2 Назначение и цели создания продукта

<a id="tz-2-1"></a>

### 2.1 Назначение системы

Система предназначена для локальной автоматизации работы учебной библиотеки: ведения фонда, поиска изданий, учёта выдач и возвратов.

<a id="tz-2-2"></a>

### 2.2 Цели создания системы

Цели: устранить двойную выдачу экземпляра, обеспечить прослеживаемую историю и дать читателю доступ к собственным выдачам. Достижение целей проверяется сценариями раздела 6.

<a id="tz-3"></a>

## 3 Характеристика объекта автоматизации

<a id="tz-3-1"></a>

### 3.1 Описание объекта

Объект — библиотека университета с несколькими филиалами и читателями разных факультетов.

<a id="tz-3-2"></a>

### 3.2 Участники процесса

Библиотекарь ведёт справочники и обслуживает выдачи; читатель регистрируется, ищет книги и контролирует сроки возврата; администратор установки запускает приложение, задаёт окружение и сохраняет резервные копии. Администратор установки не является отдельной ролью веб-приложения.

<a id="tz-4"></a>

# 4 Требования к продукту

<a id="tz-4-1"></a>

## 4.1 Функциональные требования

| Код | Требование |

|---|---|

| F01 | Регистрация создаёт только читателя с уникальным логином, именем, паролем и выбранным факультетом. |

| F02 | Вход проверяет пароль, создаёт ограниченную по времени сессию; выход отзывает её. Неавторизованный доступ к защищённому API возвращает 401. |

| F03 | Библиотекарь создаёт, просматривает, изменяет и удаляет авторов, книги, филиалы, экземпляры и факультеты. Используемые записи защищены от удаления. |

| F04 | Каталог ищет по названию, автору и ISBN/шифру без учёта регистра. Фильтры автора, филиала и наличия комбинируются. |

| F05 | Выдача связывает читателя со свободным экземпляром. Срок вычисляет сервер. Одна активная выдача на экземпляр; по умолчанию лимит 5 книг и срок 14 дней. Просрочка блокирует новую выдачу. |

| F06 | Возврат закрывает активную выдачу и сохраняет историю. Повторный возврат и изменение выданного экземпляра запрещены. |

| F07 | Библиотекарь видит все выдачи; читатель — только свои. Служебные операции защищены проверкой роли и возвращают 403 при нарушении. |

| F08 | Отчёт показывает количество изданий, экземпляров, активных и просроченных выдач, до 10 популярных книг и выдачи по факультетам за всё время. |

| F09 | Журнал показывает 100 последних успешных изменений фонда, выдач и возвратов с исполнителем и временем UTC. |

| F10 | GET /health проверяет доступ к базе и возвращает статус и версию. Команда backup создаёт согласованную резервную копию. |

<a id="tz-4-2"></a>

## 4.2 Правила данных

Книги содержат название, основного автора, год 1450–2100 и уникальный ISBN либо внутренний шифр. Экземпляр имеет уникальный инвентарный номер, книгу и филиал. Дата возврата и срок не могут предшествовать выдаче. Просрочка наступает на следующий день после due_at. Книги с экземплярами и экземпляры с историей не удаляются.

# 4 Требования к продукту продолжение

<a id="tz-4-3"></a>

## 4.3 Требования к системе в целом

Архитектура: браузер, единое HTTP-приложение и реляционная SQLite. Требуются русскоязычный интерфейс, JSON API и сохранение данных между запусками. Интерфейс должен быть пригоден для настольного экрана и ширины 390 пикселей без горизонтального переполнения страницы; широкие таблицы допускают собственную прокрутку.

Область эксплуатации версии 0.1.0 — локальная учебная установка и небольшой демонстрационный фонд. Целевые объёмы для приёмки: не менее 4 книг, 8 экземпляров, 4 авторов, 2 филиалов и 3 факультетов. Промышленная отказоустойчивость, распределённая работа и высокая нагрузка в эту версию не входят.

<a id="tz-4-4"></a>

## 4.4 Надёжность и целостность

Запись выдачи и возврата выполняется атомарно с аудитом. Внешние ключи и ограничения уникальности включаются в базе. Два одновременных запроса выдачи одного экземпляра должны приводить к одной успешной операции и одному отказу, без дубликатов. При ошибке транзакция откатывается.

Резервная копия создаётся средствами SQLite без перезаписи существующего файла. Восстановление производится после остановки приложения переключением DATABASE_PATH на сохранённую копию. Критерии проверки: integrity_check возвращает ok, каталог открывается и контрольные записи сохранены.

<a id="tz-4-5"></a>

## 4.5 Безопасность и обработка ошибок

Пароль читателя имеет длину 10–128 символов; в БД хранится только хеш. Серверная сессия по умолчанию действует 8 часов; cookie использует HttpOnly и SameSite=Lax. Роль проверяется на сервере. Изменяющие запросы требуют CSRF-токен действующей сессии. Параметры SQL передаются отдельно от текста запросов.

Ошибки возвращаются в JSON с кодом и сообщением. Предусмотрены 400, 401, 403, 404, 405, 409, 413, 422 и 500. В ответе 500 отсутствуют детали внутреннего стека. Размер тела ограничен 64 КиБ. Чужой Origin отклоняется. Debug-режим выключен.

<a id="tz-4-6"></a>

## 4.6 Виды обеспечения и программная среда

Информационное обеспечение: справочники и история в SQLite; схема описана в schema.sql. Лингвистическое: русский интерфейс, UTF-8. Программное: Python 3.11+, Flask 3.1.2, python-dotenv 1.1.1, HTML, CSS, JavaScript без сборщика. Техническое: компьютер с Python и браузером Chromium; интернет требуется для установки зависимостей. Конфигурация задаётся переменными окружения и файлом .env; образец поставляется без рабочих секретов.

### 6.1 Организация испытаний

Предварительные испытания выполняют разработчики на отдельной временной базе. В опытном использовании один участник действует как библиотекарь, второй — как читатель. Итоговую приёмку проводит преподаватель по поставляемому архиву и демонстрации.

<a id="tz-6-2"></a>

## 6.2 Критерии приёмки

| Объект контроля | Условие приёмки |

|---|---|

| F01–F02 и F07 | Регистрация и вход работают; неверный пароль, истёкшая сессия и недопустимая роль дают отказ; чужие выдачи не раскрываются. |

| F03–F04 | Операции пяти сущностей и комбинированный поиск воспроизводятся; связанные записи не удаляются. |

| F05–F06 | Выдача/возврат сохраняют историю; повторные, просроченные и сверхлимитные операции отклоняются; конкурентная выдача даёт 201 и 409. |

| F08–F10 | Отчёты соответствуют контрольным данным; аудит содержит действие; /health успешен; резервная копия целостна. |

| Комплект поставки | Все 20 тестов успешны; пройден браузерный сценарий; инструкция запуска воспроизводима; рабочие секреты отсутствуют. |
