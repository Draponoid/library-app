# Сценарий защиты лабораторной работы №1

Ориентировочное время: 7–10 минут. До демонстрации установите зависимости, выполните `setup_local.py`, запустите сервер. Пароли найдите в своей `.env`; не показывайте её на общем экране.

1. **Назначение и модель.** «Наша тема — библиотека. Книга описывает издание, экземпляр — физическую единицу в филиале. Учётная запись читателя связана с факультетом, выдача связывает читателя и экземпляр». Покажите схему из `docs/DATABASE.md`.
2. **Готовность приложения.** Откройте `/health`. Покажите версию 0.1.0 и проверку соединения с базой.
3. **Аутентификация.** На экране входа введите неверный пароль: появится понятная ошибка. Затем войдите под `librarian` с паролем из настройки.
4. **Каталог.** Найдите «МАСТЕР»; объясните поиск без учёта регистра. Выберите филиал и «В наличии», посмотрите счётчики фонда.
5. **Основные операции.** В «Управлении фондом» добавьте автора, измените его имя и удалите запись. Для книги создайте автора, затем книгу с годом и уникальным шифром, после — экземпляр с филиалом и инвентарным номером. Покажите запись в каталоге.
6. **Правило предметной области.** Оформите выдачу свободного экземпляра читателю. Экземпляр исчезнет из списка доступных. Покажите в тестах, что повторная выдача через API получает 409, включая два одновременных запроса. Объясните транзакцию и уникальный индекс.
7. **Возврат и история.** Нажмите «Принять возврат». Запись останется с датой возврата; экземпляр снова доступен для выдачи. Покажите отчёты и журнал действий.
8. **Разделение прав.** Выйдите. Зарегистрируйте нового читателя с факультетом и паролем от 10 символов. Войдите: справочники и отчёты недоступны, список собственных выдач пуст. Ранее созданный `reader` увидит свою историю.
9. **Качество и конфигурация.** Запустите `python -m unittest discover -s tests -v`, покажите успешный итог. Покажите `.env.example` без рабочих паролей, README и правила приёмки.
10. **Документация.** Откройте отчёт и техническое задание. Укажите, что по согласованному объёму этого комплекта Git-часть не выполнялась, номер версии хранится в VERSION.

## Короткие ответы на возможные вопросы

**Почему SQLite?** Это реляционная СУБД с транзакциями, внешними ключами и индексами; для локальной лабораторной не нужен отдельный сервер базы.

**Где защищается повторная выдача?** API проверяет доступность в транзакции `BEGIN IMMEDIATE`; частичный уникальный индекс дополнительно запрещает две строки с одинаковым copy_id и пустым returned_at.

**Чем аутентификация отличается от авторизации?** Вход устанавливает личность пользователя; проверка роли решает, может ли он выполнять конкретное действие. Проверки выполняются на сервере, а не только скрытием кнопок.

**Где хранится пароль?** В базе хранится scrypt-хеш с солью, не исходный пароль. В cookie находится случайный токен, в таблице sessions — его SHA-256-хеш и срок действия.

**Почему нельзя удалить книгу?** Если у книги есть экземпляры, внешний ключ защищает связанные данные. Сначала удаляются неиспользуемые экземпляры. Экземпляры с историей выдач не удаляются, чтобы сохранить историю.

**Что считать просрочкой?** Невозвращённую выдачу с due_at раньше текущей даты сервера. В сам день срока возврата просрочки ещё нет.

**Где DevOps-практики?** В воспроизводимом запуске, конфигурации через окружение, health-проверке, автоматических тестах, резервном копировании и правилах приёмки изменений. Git-процесс исключён из выполненного объёма.
