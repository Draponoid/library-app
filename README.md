# Библиотека — лабораторная работа №1

**Тема 3.** Московский политех, группа 241-351. Дисциплина: «Методология и практики DevOps». Выполнили: Махров И.М., Крамской И.М. Версия: **0.1.0**.

Приложение ведёт каталог книг, авторов, филиалов, экземпляров и факультетов, регистрирует читателей, выдачи и возвраты. Библиотекарь управляет фондом и смотрит отчёты; читатель ищет книги и видит только собственные выдачи.

## Быстрый запуск в Windows

Нужен Python 3.11 или новее с pip; проверено на Python 3.12 и Windows. Распакуйте архив, откройте терминал **в папке library-app**. Интернет нужен для первой установки зависимостей.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe setup_local.py
.venv\Scripts\python.exe app.py run
```

Откройте **http://127.0.0.1:5000**. Остановка сервера: Ctrl+C. Если `python` не найден, установите Python с добавлением в PATH либо используйте `py -3` для первой команды.

`setup_local.py` выполняется **один раз**: создаёт `.env` со случайными паролями и ключом, затем демонстрационную базу. В терминале появятся логины `librarian` и `reader` с индивидуальными паролями. Эти пароли также записаны в `.env`. При следующих запусках выполняйте только последнюю команду. Существующий `.env` не перезаписывается.

Альтернатива для PowerShell 7: `./start.ps1` — создаёт окружение, устанавливает зависимости, при отсутствии `.env` выполняет начальную настройку и запускает приложение. Если политика PowerShell запрещает сценарий, используйте четыре команды выше.

Для Linux/macOS: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -r requirements.txt`, `.venv/bin/python setup_local.py`, `.venv/bin/python app.py run`.

## Проверка после запуска

1. Откройте `/health`: ожидаются `status: ok`, `database: ok`, `version: 0.1.0`.
2. Войдите как библиотекарь с паролем из `.env`. В каталоге находятся четыре книги и восемь экземпляров.
3. Откройте «Выдачи и возвраты», выберите экземпляр и читателя, оформите выдачу.
4. Примите возврат, затем откройте «Отчёты» и «Журнал действий».
5. Выйдите и войдите как читатель: управление фондом и отчёты недоступны, отображаются только его выдачи.

Полный сценарий защиты: [docs/DEMO.md](docs/DEMO.md).

## Что реализовано

- Веб-интерфейс на русском языке, адаптированный под настольный и мобильный экран.
- Регистрация читателей, вход, выход, серверные сессии с истечением срока, хеширование паролей scrypt.
- HTTP JSON API и реляционная SQLite с внешними ключами и индексами.
- Создание, просмотр, изменение и удаление книг, авторов, филиалов, факультетов и экземпляров.
- Поиск по названию, автору, ISBN/шифру без учёта регистра; фильтры автора, филиала и наличия.
- Выдача на 14 дней; максимум 5 активных выдач; запрет новых выдач при просрочке.
- Защита от двух активных выдач одного экземпляра, в том числе при одновременных запросах.
- Возврат с сохранением истории; запрет повторного возврата и изменения выданного экземпляра.
- Отчёты о фонде, просрочках, популярных книгах и выдачах по факультетам.
- Журнал последних 100 изменений, JSON-ошибки, CSRF-защита, служебный адрес `/health`.
- Команда согласованного резервного копирования SQLite.

У книги один основной автор. Для коллективного авторства модель можно расширить связующей таблицей в следующей версии. Поле `isbn` допускает внутренний шифр; значения `DEMO-001` и т.п. — демонстрационные шифры, не настоящие ISBN. Отчёты вычисляются по данным, отдельной таблицы отчётов нет. Кэширование не требуется в ЛР1 и пока не реализовано.

## Конфигурация

Переменные окружения имеют приоритет над `.env`. Относительный путь базы отсчитывается от папки приложения.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| SECRET_KEY | обязателен, минимум 32 символа | Секрет конфигурации Flask; сессии хранятся отдельно в SQLite |
| DATABASE_PATH | data/library.sqlite3 | Путь к базе |
| HOST | 127.0.0.1 | Интерфейс прослушивания |
| PORT | 5000 | HTTP-порт |
| SESSION_HOURS | 8 | Срок сессии, целое положительное число |
| COOKIE_SECURE | false | true только при работе через HTTPS |
| LOAN_DAYS | 14 | Продолжительность выдачи в днях |
| MAX_ACTIVE_LOANS | 5 | Лимит активных выдач читателя |
| DEMO_LIBRARIAN_PASSWORD | задаётся при настройке | Пароль librarian при init-demo |
| DEMO_READER_PASSWORD | задаётся при настройке | Пароль reader при init-demo |

При ручной настройке скопируйте `.env.example` в `.env`, замените ключ и оба пароля, выполните `python app.py init-demo`. Изменение паролей в `.env` **не меняет уже созданные учётные записи**. Для восстановления утраченного доступа в учебной установке можно восстановить сохранённую базу. Интерфейс сброса пароля в версии 0.1.0 не предусмотрен.

## Тесты и приёмка

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m compileall -q app.py setup_local.py tests
```

Тесты создают отдельную временную базу и не изменяют пользовательские данные. Проверено 20 тестов, включая конкурентную выдачу. Результаты и браузерные сценарии: [docs/TEST_REPORT.md](docs/TEST_REPORT.md). Правила внесения изменений и обязательные команды: [CONTRIBUTING.md](CONTRIBUTING.md).

## Резервная копия и восстановление

```powershell
.venv\Scripts\python.exe app.py backup --output backups/library-2026-09-19.sqlite3
```

Используется SQLite Backup API; допустимо копирование работающей базы. Файл назначения должен быть новым. Для восстановления остановите приложение, сохраните текущую базу, укажите путь к файлу резервной копии в `DATABASE_PATH` и снова запустите приложение. Так не требуется удалять исходную базу или её служебные файлы. Сначала проверьте каталог и `/health`. Копия содержит пользователей, хеши паролей и сессии: храните её с ограниченным доступом. Восстановление возвращает состояние всей базы на момент копирования.

## Git и CI/CD

Публичный репозиторий: https://github.com/Draponoid/library-app.
Основная ветка — `master`. Ветка `features` создана от готового `master` для будущей работы, без отдельных изменений.

Workflow `.github/workflows/ci-cd.yml` запускается при push в `master` и `features`, pull request в `master`, а также вручную. Он устанавливает зависимости, запускает 20 тестов, проверяет синтаксис Python/JavaScript, собирает Docker-образ и проверяет `/health` и главную страницу работающего контейнера. Только успешный запуск для `master` публикует тот же проверенный образ в GHCR:

- `ghcr.io/draponoid/library-app:latest`;
- `ghcr.io/draponoid/library-app:sha-<полный SHA коммита>`.

Публикация использует встроенный `GITHUB_TOKEN`, отдельный пароль реестра не нужен. CD здесь означает доставку образа в реестр; автоматического развёртывания на удалённый сервер нет. Видимость пакета GHCR настраивается отдельно от видимости репозитория; для приватного пакета требуется `docker login ghcr.io` с правом чтения пакетов.

## Docker

Нужен запущенный Docker с поддержкой Linux-контейнеров и Docker Compose. Скопируйте `.env.example` в `.env`, замените `SECRET_KEY` случайной строкой не короче 32 символов и задайте два разных демонстрационных пароля длиной 10–128 символов. `.env` не публикуется в Git и не попадает в образ.

```powershell
# Собрать образ локально
 docker compose build
# Только один раз для нового пустого тома: создать пользователей и демоданные
 docker compose run --rm library python app.py init-demo
# Запустить приложение
 docker compose up -d --no-build
# Проверить состояние и логи
 docker compose ps
 docker compose logs --tail 50
# Остановить, сохранив базу
 docker compose down
```

Откройте http://127.0.0.1:5000. Вход: `librarian` или `reader`, пароль — заданный в `.env`. Вместо локальной сборки можно выполнить `docker compose pull`, чтобы получить опубликованный образ, затем те же команды инициализации и запуска. Повторная инициализация заполненной базы намеренно запрещена.

В контейнере используется Waitress на порту 5000 и непривилегированный пользователь. SQLite хранится в постоянном томе `library-data` по пути `/data/library.sqlite3`. Локальная база из `data/` автоматически в том не переносится. `docker compose down` сохраняет том; **не используйте `down -v`, если данные нужны**. Новый образ не стирает базу. Перед изменениями схемы нужна отдельная миграция и резервная копия.

Проверка контейнера не заменяет прикладные тесты: обе стадии обязательны. Dockerfile копирует только код, схему, статические файлы и зависимости; пользовательские базы, пароли, IDE и Git-история исключены.
